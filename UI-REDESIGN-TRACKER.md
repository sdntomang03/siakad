# UI Redesign Tracker

This tracker covers the 121 Blade templates under `resources/views`. A shared layout or control update does not count as a page-level redesign. Access context is marked unknown unless it is explicit in the view; controller and middleware authorization are outside this visual review.

## Status

| Status | Meaning |
| --- | --- |
| Updated | Page-specific visual changes are complete. Shared application checks and targeted interaction checks are recorded below; not every workflow on every view was manually exercised. |
| Shared shell only | The view inherits the redesigned shell and/or common brand-color, corner-radius, and page-heading harmonization; its page-specific layout has not been redesigned. |
| Pending | No redesign work has been done on this view. |

## Preservation checks

- Routes, controllers, models, schemas, middleware, authentication, authorization and business workflows remain outside the redesign scope.
- Existing navigation names and role gates are retained.
- No placeholder metrics or fake records have been added.

## Verification

- `php artisan view:clear` and `php artisan view:cache` passed.
- `php artisan test` passed: 33 tests and 88 assertions.
- `npm run build` passed. Vite reported stale Browserslist `caniuse-lite` data.
- `git diff --check` passed; Git emitted only line-ending conversion warnings for existing CRLF files.
- Browser smoke checks passed on the authenticated teacher dashboard at 390, 768 and 1280 pixels with no horizontal overflow. The mobile navigation closes with Escape, the mobile user menu opens, the desktop sidebar expands, and the teacher's KBM navigation group expands and exposes its links.
- Browser checks also covered Renkin tab/search/copy keyboard behavior and the graduation portal's labels, required-field validation, landmarks, responsive widths and reduced-motion behavior.
- The sidebar's four distinct role/ability directive expressions and 22 named routes, plus the account navigation's two named routes, match the pre-redesign versions. A teacher account was available for live navigation checks; other roles were not separately authenticated in the browser.
- No PHP view compilation, test, or frontend build failures were observed. Interactive workflows across all 121 templates were not individually browser-tested; PDF/print templates intentionally retain their document-specific layout.
